Example Applications

QuickFIX includes several example applications in the examples/ directory to demonstrate various FIX application patterns. The Java ones are in src/java/examples/.

ordermatch

ordermatch is a C++ server application that implements a simple matching engine. It accepts limit orders and matches them when buy and sell orders cross. It is in Java too, with the same console: type a symbol to see its book, #symbols to list the symbols, #quit to stop. This example demonstrates:

  • FIX acceptor implementation
  • Order management and matching logic
  • Execution reports and order status handling
  • Multi-session support

tradeclient

tradeclient is a C++ console-based trading client that allows you to interactively send orders and view executions. This example demonstrates:

  • FIX initiator implementation
  • Interactive order entry
  • Message creation and sending
  • Receiving and displaying execution reports

banzai

banzai is a Java trading client with a window, upstream's former tradeclientgui on this fork's Java binding. Orders are entered in the window and sent on any session logged on; their state and fills show in tables as the execution reports come back, and the order selected can be cancelled or replaced. It sends in each session's version of FIX, 4.0 to 4.4 and 5.0, and trades with ordermatch and the executors. This example demonstrates:

  • The Java binding's callbacks handing messages to a GUI thread
  • Order, cancel and replace messages for each FIX version
  • Following an order's state through its execution reports

executor

executor is a simple server that automatically fills every limit order it receives. This example is available in multiple languages to demonstrate language binding usage:

  • C++ - Full-featured implementation
  • Python - Demonstrates Python bindings
  • Ruby - Demonstrates Ruby bindings
  • Java - Demonstrates the Java binding; fills FIX 4.4 orders only

The executor example is particularly useful for testing trading clients and demonstrates basic order execution flow.

Running the Examples

Build with the examples enabled (-DQUICKFIX_EXAMPLES=ON, the default). The programs land in lib/, and bin/ holds links to them, their configuration files (bin/cfg/) and a script per example, runnable from anywhere:

  • bin/run_executor_cpp.sh, bin/run_executor_ssl_cpp.sh (TLS)
  • bin/run_executor_python3.sh (needs -DHAVE_PYTHON3=ON), bin/run_executor_ruby.sh (needs src/ruby/make_ruby.sh)
  • bin/run_ordermatch.sh
  • bin/run_tradeclient.sh, bin/run_tradeclient_ssl.sh (TLS)
  • bin/run_executor_java.sh, bin/run_ordermatch_java.sh and bin/run_banzai.sh (need -DHAVE_JAVA=ON; each compiles its example first, and Banzai needs a display)

Start an executor or ordermatch, then a tradeclient or Banzai in another terminal. The TLS runs use the certificates in bin/cfg/certs/; their keys are public, for the examples only (see bin/cfg/certs/README).

Using Examples as Templates

These examples serve as excellent templates for building your own FIX applications. They demonstrate:

  • Application interface implementation
  • Message handling and routing
  • Configuration file setup
  • Error handling patterns
  • Best practices for FIX applications
